## 6. 测试过程发现

1. `docker compose up --build -d` 首次失败在 Docker registry mirror：`docker.mirrors.ustc.edu.cn ... EOF`，尚未进入业务代码构建。
2. `docker compose up --build --pull never -d` 仍触发 BuildKit metadata lookup；`DOCKER_BUILDKIT=0 docker compose up --build -d` 仍因缺少本地 Python base image失败。
3. 为完成 Docker 验证，使用本地已有 `maven:3.9-eclipse-temurin-17` 作为 API runtime base，执行 `DOCKER_BUILDKIT=0 docker compose build api` 成功，再用 `docker compose up -d --no-build` 启动完整栈。
4. 额外验收检查：重复上传同名文件返回 409 而不是 500；每张上传图片文件端点返回 200；`docker compose restart api` 后上传文件仍返回 200，验证 volume 持久化。
5. API 日志抽样显示本次命中 `/api/images/canny` 与 `/api/images/correction/align`，未在抽样输出中看到相关异常。
6. 浏览器 UI 验证：登录 `admin/admin123` 后进入 `/toolbox/image-correction`，可见上传入口与“根据模板自动矫正”入口；当前浏览器控制 API 不提供文件选择器注入能力，因此文件上传/自动校正的真实文件流由 Docker API 测试验证。
