## 3. 推荐协作流程

### 3.1 分支

```bash
git pull origin main
git checkout -b feat/<模块>-<简述>   # 例：feat/report-pages-api
```

### 3.2 开发环境（统一）

```bash
cp .env.docker.example .env
docker compose up --build -d
# API http://localhost:8080  前端 http://localhost:3000  账号 admin/admin123
```

**注意：**

- 旧 MySQL volume 可能缺 `regions` 表 → 重启 API 会跑 `schema_patch.sql`；仍失败则 `docker compose down -v` 重建。
- PRJ-04 全链路 run 依赖容器内 `/app/storage/test-assets/`；`run-p0-p1.sh` 会自动 seed（`model_image.jpg`、`butterfly.json`、`edge.json`）。

### 3.3 提 PR 前必做

```bash
bash tests/scripts/run-p0-p1.sh
# 确认 PRJ-04 task=success；更新 tests/results/latest-run.txt（脚本自动写）
```

PR 描述请包含：

1. 对应用户旅程哪一步
2. 改了哪些 API / 页面
3. `run-p0-p1.sh` 结果（PASS/FAIL 数）
4. 是否需要数据库迁移（改 `schema_patch.sql` 或 init SQL）

### 3.4 API 约定（避免再踩坑）

| 项 | 约定 |
|----|------|
| 鉴权 | `Authorization: Bearer <JWT>` |
| 创建项目 ownerId | 传 admin 的 **UUID**，不是用户名 `admin` |
| 上传 multipart | 字段名 `file`；**不要**在 axios 里写死 `Content-Type: multipart/form-data` |
| Canny / 角点 | multipart 字段名 `file`（不是 `image`） |
| 分析 run | `POST /api/projects/{id}/run`；停止 `POST .../stop` |
| 模板创建 | `POST /api/templates` multipart：必填 `name`、`imageFile`；`regionsJson` 仅兼容旧数据，v1.0 区域在项目步骤 3 定义 |
| PRJ-04 通过标准 | HTTP 200 **且** `tasks[0].status === success` |

契约细节：`API-INSPECTION-REPORT.md`、`backend/APIdoc/`。
